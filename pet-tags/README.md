# Сайт адресников для питомцев: главная + 3D-конструктор

- **`index.html` — главная для привлечения заявок.** 3D-витрина готовых работ, преимущества, «Как заказать»,
  готовые идеи (откроются в конструкторе для правки), прозрачные цены, форма заявки на консультацию,
  частые вопросы, кнопки мессенджеров, SEO-разметка (FAQ и товар в schema.org).
- **`constructor.html` — 3D-конструктор.** Клиент собирает адресник (форма, материал, гравировка, шнурок,
  бусины, стразы, допы), видит цену построчно и оформляет заказ.
- **`privacy.html`** — политика обработки персональных данных (152-ФЗ). ⚠️ Впишите свои данные вместо `[...]`.

## Запуск локально
```bash
cd pet-tags && python3 -m http.server 8000   # http://localhost:8000
```
Сборка не нужна: HTML/CSS/JS, Three.js подключается с CDN.

## Управление сайтом — админка `/admin` (Sveltia CMS)
Цены и названия всех позиций, контакты, сроки, доставку, оплату, обещания, отзывы, FAQ и реквизиты
мастер правит в **monavita.ru/admin**. Данные хранятся в `content.json`.
- **Вход по логину и паролю** (кнопка «Войти через GitHub» открывает форму входа нашего сайта). Владелец один раз
  выпускает fine-grained токен GitHub с доступом только к `Egorov456/CODEX` и правом **Contents: Read and write**,
  затем на сервере выполняет:
  ```bash
  CMS_USER=Admin CMS_PASSWORD='пароль' CMS_GITHUB_TOKEN=github_pat_… bash pettags-install.sh install
  ```
  Пароль хранится только в виде хеша (PBKDF2), токен лежит в `/etc/pettags.env` (права 600). После 5 неверных
  паролей вход с этого IP блокируется на 15 минут. Сменить пароль: повторить команду с новым `CMS_PASSWORD`.
  Запасной вход: «Sign In Using Access Token» с личным токеном GitHub.
- **Сохранение** = коммит в `main` → сайт обновляется сам примерно за 5 минут. История и откат любой правки — в git.
- **Защита:** перед выкладкой `deploy/validate_content.py` проверяет файл (цены 0–100 000, названия не пустые, все позиции на месте).
  Если файл битый, установка останавливается, и сайт остаётся на прошлой версии (журнал: `journalctl -t pettags`).
- Добавить новую форму, материал или бусину можно только в коде, потому что у них есть 3D-модель: сначала id в `js/config.js`, затем цена в `content.json`.
- CMS закреплена на версии 0.249.1 с проверкой хеша (SRI). Обновлять её нужно осознанно: поменять версию и `integrity` в `admin/index.html`.

## Технические настройки — `js/config.js`
- id позиций, палитры, лимиты, 3D-параметры; материалы, узоры (`patterns`), фигурки на адреснике (`toppers`),
  бусины и подвески (`beads`, `group: 'charm'`), ошейник-бусы (`cords`); готовые идеи (`presets`); вопросы-ответы (`faq`);
- номер счётчика Яндекс.Метрики задаётся в админке (цели: `open_constructor`, `lead_submit`,
  `order_submit`, `advice_click`, `messenger_click` — создайте их в Метрике как «JavaScript-событие»);
- `orderEndpoint` — адрес приёма заявок (см. ниже).

## Заявки и заказы в Telegram
Без сервера клиент отправляет готовый текст заявки/заказа в WhatsApp или Telegram сам.
Чтобы всё приходило автоматически (с фото макета для заказов):
1. Создайте бота у @BotFather → токен; напишите боту, узнайте свой chat id (например, @userinfobot).
2. Задеплойте папку `pet-tags` на Vercel (Root Directory = `pet-tags`), добавьте переменные
   `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.
3. В `config.js` укажите `orderEndpoint: '/api/order'`.
Если сервер недоступен, клиенту автоматически показываются кнопки мессенджеров. От ботов — скрытое поле-ловушка.

## Сервер (VPS): контакты, Telegram и CRM
Все настройки сохраняются в `/etc/pettags.env` и **переживают автообновление**:
```bash
CONTACT_WHATSAPP=79991234567 CONTACT_TELEGRAM=nick \
TELEGRAM_BOT_TOKEN=... TELEGRAM_CHAT_ID=... bash install.sh install
```
Контакты лучше указывать в админке. `CONTACT_*` на сервере перекрывают их при каждой выкладке.
Если на сайте остались заглушки (`79990000000`, `your_telegram`), установщик предупредит.

### Заявки в EspoCRM (необязательно)
Каждая заявка и заказ становятся **лидом** в EspoCRM: имя, телефон, сумма, полный текст заказа и макет PNG (заметкой).
В Telegram приходит ссылка на карточку. Если CRM недоступна, заявка всё равно уходит в Telegram, и наоборот.
1. `bash install.sh crm` поднимает EspoCRM 10 в Docker на `127.0.0.1:8090` (пароль admin лежит в `/opt/pettags-crm/.env`).
   Docker на сервер с VPN установщик **не ставит**: он меняет iptables. Если Docker не установлен, используйте отдельный VPS с `deploy/crm/docker-compose.yml`.
2. Откройте CRM снаружи по HTTPS, например в Caddy: `crm.monavita.ru { reverse_proxy 127.0.0.1:8090 }`.
3. В CRM: Администрирование → Роли → роль «Сайт» (Лиды: создание и чтение; Заметки и Вложения: создание) →
   API-пользователи → создать с этой ролью, способ «API Key», скопировать ключ.
4. Настройте статусы лида под воронку: Администрирование → Менеджер сущностей → Лид → поле «Статус»
   (Новая → Связались → Макет согласован → Оплачено → В работе → Отправлено → Получено / Отказ).
5. `ESPO_URL=http://127.0.0.1:8090 ESPO_PUBLIC_URL=https://crm.monavita.ru ESPO_API_KEY=... bash install.sh install`

Тесты: `python3 -m unittest discover -s deploy -p 'test_*.py'` (приём заявок и проверка контента) и `node --test deploy/test_config.mjs`. CRM поддерживается только в VPS-варианте (`deploy/order_server.py`), а не в `api/order.js` для Vercel.

## Структура
- `js/landing.js` — главная; `js/app.js` — конструктор; `js/scene.js` — 3D-сцена (витрина, превью, конструктор);
- `js/shapes.js` — формы; `js/pricing.js` — цены и тексты заказа; `js/send.js` — отправка и аналитика;
- `api/order.js` — приём заявок/заказов и пересылка в Telegram.
